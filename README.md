# AI-Native Video Editing Platform

Linux デスクトップ向けの、AI アシスト付き非破壊動画編集ソフトウェア。
`Rust + egui + wgpu + FFmpeg` で実装されている。

## Project Goal

既存の動画素材をAIが理解・検索・評価・編集できるようにする、AIネイティブな非生成型動画編集プラットフォーム。

このプロジェクトは動画生成AIを主目的としない。

**核心思想**

> 動画を生成するAIではなく、既存動画を理解し、必要な部分だけ観察し、編集するAIを実現する。

また、特定AIベンダーへの依存を避ける。

> AIモデルを作るのではなく、どんなAIでも動画編集に参加できる土台を作る。

## Overview — いまの姿

- Linux デスクトップのネイティブ NLE（非線形編集ソフト）。Web 技術は使わない。
- マルチレイヤー・タイムライン、トリム／分割／倍速／キーフレーム／エフェクト、
  テキスト・図形・VOICEVOX セリフの合成、FFmpeg による MP4 書き出しまで一通り動く。
- プレビューは書き出しと同じ合成順で描画する。**重なり合う音声を同時再生**し、
  **複数の映像レイヤーを Z 順に合成**するので、「見たまま」が書き出しに近づく。
- AI は解析（シーン検出・OCR・文字起こし）、意味検索、ツール実行型アシスタントとして
  編集に参加する。AI はメディアを直接書き換えず、すべて非破壊コマンドを通る。
- プロジェクトはバージョン付き JSON（`.yukivproj`）。**旧ファイルの読み込みは保証される。**

## Architectural Principle

```text
User
  ↓
Editor UI
  ↓
Editing Core
  ↕
Video Knowledge Engine
  ↕
AI Agent
  ↕
AI Provider Adapter
  ↕
Any Compatible AI
```

AIモデルは交換可能であり、編集コアはAIから独立する。

## Key Differentiator

長時間・大量の動画をAIのコンテキストへ直接投入しない。

代わりに、

```text
Video
→ Analysis
→ VIR
→ Search / Retrieval
→ Frame / Clip Observation
→ AI Reasoning
→ AEP
→ Editing Core
→ Export
```

とする。

AIは動画そのものを常時保持するのではなく、必要な情報をツール経由で取得する。

## Project Doctrine

1. Original media is immutable.
2. Editing is non-destructive.
3. AI does not directly mutate media files.
4. VIR is the semantic representation of media.
5. AEP is the AI-to-editor control protocol.
6. AI providers are replaceable.
7. Visual context is retrieved progressively.
8. Read and write tools are separated.
9. Project state must be deterministic and recoverable.
10. Standards and interoperability are first-class features.

## MVP

最初の完成目標は「Premiere Pro級の全部入り」ではない。

```text
Import video
→ Scene detection
→ Transcript / OCR / keyframes
→ VIR
→ Scene search
→ AI observes frames
→ AI creates AEP
→ Timeline applies AEP
→ Export
```

このループを完成させることを優先する。

## Quick Start

1. **開く / 保存** — メニュー「ファイル」からプロジェクトを開く・保存（`Ctrl+S`）。拡張子は `.yukivproj`。
2. **メディアを取り込む** — 「ファイル → メディアを追加…」、ツールバーの「＋ファイル」、または OS 上のファイルをウィンドウへ**ドラッグ＆ドロップ**（タイムライン上に落とすと、その時刻へ配置される）。
3. **タイムラインで編集** — クリップの移動・トリム・分割・倍速・エフェクト・キーフレーム、テキスト／図形／VOICEVOX セリフの追加。レイヤーは自由に混在できる汎用トラック。
4. **プレビュー** — `Space` で再生。重なり合う音声と複数レイヤーの映像を書き出しと同じ順で確認できる。
5. **書き出す** — 「ファイル → 動画を書き出す…」。コーデック・品質・音声ビットレートを選んで MP4 生成。QSV があれば利用。

### 基本操作

- `Ctrl+S`: プロジェクト保存 / `Ctrl+Z`・`Ctrl+Shift+Z`: Undo / Redo
- `Space`: 再生・一時停止 / `←` `→`: 1フレーム送り / `Home` `End`: 先頭・末尾
- `Delete`: 選択アイテム削除 / `Ctrl+C`・`Ctrl+V`: コピー・再生位置へペースト
- タイムラインの赤いプレイヘッドをドラッグ、またはルーラー／空白をクリック・ドラッグでシーク
- アイテムのボディをドラッグで移動、左右端をドラッグでトリム
- プレビュー内のテキスト／図形を直接ドラッグで移動、右下ハンドルでサイズ変更

## Preview Fidelity — プレビューの忠実度

- **音声**: 再生ヘッド上で鳴っているクリップをすべて同時再生する（それぞれにゲイン・速度を適用）。書き出しの `amix` と同じ「重なって鳴る」挙動。
- **映像**: 見えている映像クリップをレイヤー順（奥→手前）にテクスチャ合成。テキスト・図形も同じ順で重なる。書き出しのコンポジット順と一致させる方針。
- プレビューで見た重なりは、書き出しでも同じ重なりになる。サンプル単位の完全一致ではなく「見たまま」の忠実度。

Linux向けのPhase 1基礎エディタを、Web技術を使わない`Rust + egui + wgpu`構成で実装している。

現在利用できる機能:

- ドッキング可能なパネル群（上記「Panel System」参照）。表示／非表示は「表示」メニューで切り替え
- FFprobeによる動画・音声・画像メタデータ取込
- 継続デコーダーによるタイムライン再生、シーク、音声プレビュー、1フレーム単位のステップ再生
- YMM4風の汎用レイヤー・タイムライン: レイヤーは動画クリップ・テキストを自由に混在させられる汎用トラックで、ロック／表示切替／ミュート、上下並べ替え、名前編集に対応
- タイムライン上でのドラッグ移動・端のドラッグによるトリム・スナップ（再生位置や他アイテムの端に吸着）に対応
- タイムラインの赤い再生バー（プレイヘッド）を直接つかんでドラッグ、またはルーラー／空白部分をクリック・ドラッグでシーク可能
- OS上の動画・音声・画像ファイルをタイムラインへ直接ドロップ、またはツールバーの「＋ファイル」ボタンから直接追加（複数ファイルの一括選択にも対応）
- 画像（PNG/JPEG/WebP/BMP/TIFF/AVIF/HEIC/HEIF/JXL）を静止画クリップとして取り込み、プレビュー・書き出しに対応。画像は固有の尺を持たないため、取込時は既定5秒で配置し、右端ドラッグやインスペクタで任意の長さへ伸ばせる（アニメーションGIFは短い動画として取り込み、アニメーションを保持）
- 音声のみのメディア（MP3/WAV/M4A/AAC/FLAC/OGG）も読込・タイムライン配置・書き出しに対応
- メディアブラウザからの素材の再配置、一度読み込んだ素材の再利用メニュー
- アイテムのコピー＆ペースト: 選択中アイテムを **Ctrl+C** でコピー、**Ctrl+V** で**再生位置にそのまま複製**（トリム・変形・エフェクト・キーフレームも保持。新しいIDで複製されるので元アイテムとは独立。Undo対応。メニューの「編集」からも実行可。テキスト入力中はOSのクリップボードを優先）
- クリップの分割、トリム、移動、削除、位置・拡大率・基準点（アンカー）・回転（角度）・不透明度によるピクチャーインピクチャー合成
- クリップの**倍速再生**（0.1×〜8.0×、プリセット0.25/0.5/1/1.5/2/4）。尺とソース対応が自動で変わり、映像・音声の両方が書き出しとプレビューに反映される
- クリップの**エフェクト**: 明るさ・コントラスト・彩度・色相・ぼかし・モノクロ・色反転（インスペクタの「✨ エフェクト」、リセットボタン付き）

- テキストの内容・フォント（システムフォント選択、太字／斜体）・整列・行間・縁取り（太さ・色）・影（オフセット・色）・背景ボックス・フェードイン／アウト・ピクセル単位の位置とアンカー・拡大率・回転を編集可能
- 選択したシステムフォントはプレビューにも読み込まれ、色・縁取り・影・背景・フェードを含む実際の見た目で表示される（プレビューと書き出しが一致）
- テキストスタイルを「テンプレート」として保存・編集・削除でき、既存テキストやVOICEVOX読み上げテキストへ一括適用可能（専用「テンプレート」タブ）
- 図形（長方形・楕円）をタイムラインに配置し、種類・色・濃度（不透明度）・大きさ・縦横比・位置・アンカー・拡大率・回転を編集可能（プレビュー・書き出しとも反映）
- プレビュー画面内でテキスト／図形オブジェクトを直接クリック選択・ドラッグ移動・ハンドルドラッグでサイズ変更可能（選択枠・背景ボックスは整列設定に関係なく文字と一致）
- VOICEVOX連携（下記参照）
- プレビュー下のツールバー（再生／一時停止／フレーム送り／分割／削除／Undo・Redo／テキスト追加／図形追加／メディア追加）
- 720p／1080p／4K解像度と23.976～60fpsプリセットを含むプロジェクト設定
- QSV対応環境ではプレビューとH.264書き出しにQSVを優先使用
- クリップ音量とミュート
- Undo / Redo
- 非破壊・バージョン付き`.yukivproj`保存と読込（下記「Project Format」参照）
- FFmpegによる映像・音声合成とMP4書き出し（レイヤーZ順・変形・回転・倍速（setpts/atempo）・エフェクト・キーフレーム・縁取り・影・背景ボックス・フェード・図形を反映）
- 書き出し設定（FFmpeg）エディター: 映像コーデック（libx264／libx265／libsvtav1・libaom-av1のAV1／libvpx-vp9、およびQSV・NVENCのH.264/HEVC/AV1）、品質CRF、プリセット、音声コーデック、音声ビットレート、エンコードスレッド数を選択可能。利用できないエンコーダーは選択不可として表示し、失敗時は自動的にlibx264へフォールバック（MP4のサンプルエントリータグもコーデック別に付与）

- 省電力・バランス・高性能の3動作プロファイル

## Project Format

- プロジェクトは**バージョン付き JSON**（`.yukivproj`、スキーマ 0.3）。詳細は `PROJECT-FORMAT.md` を参照。
- **過去に保存したプロジェクトが開けなくなる変更は行わない**（フィールドのリネーム・削除・型変更の禁止、新規フィールドは `serde` デフォルト付き）。読み込み時に旧スキーマの不整合は自動修復される（図形の重複 `kind` キー、旧 VOICEVOX セリフの音声＋字幕ペア統合）。
- 倍速・回転・エフェクト・キーフレームなどの新フィールドはすべて後方互換。
- パネルレイアウト（`dock_layout_v6`）は eframe の設定ストレージ側に保存され、プロジェクトファイルには含まれない。

## VOICEVOX連携

1. 別途VOICEVOX Engineを起動する（例: `http://127.0.0.1:50021`）。本アプリはVOICEVOX Engineを内包しない。
2. 画面下部の「🎙 VOICEVOX」欄にEngineのURLを入力する。
3. 「キャラクター」タブでキャラを作成する。キャラはYMM4のように、話者ID・声の調整（話速・音高・抑諦・音量・前後の無音）・字幕テンプレート（フォント・サイズ・位置・色・縁取りなど）を一つの単位としてまとめて持つ。同じ話者で喋り方を変えたキャラも作れる（「複製」が便利）。キャラは保存される。
4. 画面下部の「キャラ」で使うキャラを選び、読み上げるテキストを入力して **Enterキー**（または「生成」ボタン）を押すと、`audio_query` → `synthesis` のHTTPリクエストを実行し、返ってきたWAV（音声）と同じ長さの字幕を、現在の再生位置へ**1つのセリフアイテム**として追加する。追加が完了すると入力欄は自動でクリアされるので、そのまま次のセリフを続けて入力できる。字幕にはそのキャラのスタイルが使われる。セリフアイテムは音声と字幕が一体化しており、タイムライン上で移動・トリム・削除すれば両方が一緒に動く。インスペクタでは字幕（内容・フォント・縁取りなど）と音量・ミュートを編集でき、字幕の長さを変えると音声も同じ長さにトリムされる。
   - セリフを右クリック →「✂ 再生位置で分割」（または再生バーを合わせてツールバーの「✂ 分割」）で、音声と字幕を同時に2つへ分割できる。ツッコミなどでセリフをプツっと途切れさせたいときは、分割後に不要な後半を削除する。
5. キャラを使わず話者IDを直接指定したいときは「キャラ」で「直接指定」を選び、表示される「話者」欄にIDを入力する。

AIアシスタントの `add_speech` でも `character` にキャラ名を渡せば、同じキャラ設定で音声＋字幕が1つのセリフアイテムとして生成される。

生成された音声WAVは `~/.cache/yuki-video-editor/voicevox/`（または `$XDG_CACHE_HOME` 配下）に保存される。

## AI Features

### AI解析（② 素材の解析）

「AI」タブは「① AIモデル → ② 素材の解析 → ③ AIアシスタント → ④ 意味検索（任意）」の一つのワークフローにまとまっている。解析は手動でもよいし、**AIアシスタントに頼めば `analyze_media` ツールで自動で実行**され、そのまま編集に進む。

1. メディアをタイムラインへ追加する（解析対象はプロジェクト内の素材）。
2. 「AI」タブの「② 素材の解析」で対象メディアと解析設定を選ぶ（カット検出／シーン境界のしきい値、最大シーン長、OCR、文字起こし）。
3. 「解析開始」を押すとバックグラウンドで解析が走り、進捗が表示される。
4. 完了するとシーン一覧（サムネイル・時間範囲・文字起こし・OCR・重要度）が表示され、行をクリックするとその位置へシークする。「⭳ VIRを書き出す」でJSONとして保存でき、外部チャットAIや他ツールへ渡せる。

解析結果は派生物として `~/.cache/yuki-video-editor/analysis/<指紋>/` にキャッシュされ、設定や解析バージョンが変わると自動で無効化される。元メディアは一切変更しない。

### AIモデルと意味検索（ローカル／ネットワーク）

AIモデルはローカル（Ollama／llama.cpp／LM Studio）とネットワーク（OpenAI互換API・DeepSeek）のどちらでも使える。「🔌 接続テスト」「🧠 埋め込みを生成」「🔍 検索」で、解析済みシーンのテキスト（文字起こし・OCR・要約）をベクトル化して意味検索できる。モデルを設定しなくても解析（Phase 2）は動作する。APIキーは環境変数またはセッション内の入力欄から読み、保存しない。

### AIアシスタント（③ 動画制作・DeepSeekなど）

「AI」タブの「③ AIアシスタント（動画制作）」から、作りたい動画を自然言語で指示するだけで、AIが内蔵ツールを使って編集体験を進める。

1. 「① AIモデル」→「チャットモデル」でモデルを選ぶ（DeepSeek／OpenAI／ローカルのOllamaなど）。
2. 例:「この素材で30秒の紹介動画を作って。ナレーションも入れて、最後にテロップを入れて書き出して」のように入力して「送信」する。
3. AIは `get_project_state` で現状を確認し、`analyze_media`（②の解析）→ `search_scenes` → `get_frame`（キーフレーム画像の確認）を経て、カット（`split_clip` / `delete_clip` / `trim_clip` / `move_clip`）、`add_media`、VOICEVOXの声入れ（`add_speech`）、テロップ（`add_text`）、音量（`set_volume` / `mute_clip`）、書き出し（`export_video`）を順に呼ぶ。
4. 書き出しが終わると「動画が完成しました。再生してご確認ください。」と応答する。

すべての編集は編集コアの通常コマンド（`EditCommand`）を通り、非破壊で「元に戻す」で戻せる。「ツール実行を許可」をオフにするとAIはツールを実行せず操作案を提示するだけになる。ツール呼び出しに対応しないモデルや、本文にAEP（JSON）を返すモデル向けには、そのプランを検証してから適用する経路も残している（`validate_aep` + トランザクション適用）。

## Resource Policy

- UI待機中は連続再描画しない。
- プレビューはbounded queueで古い要求の蓄積を防ぐ。
- プレビューで使ったRGBバッファはデコーダへ返却して再利用し、フレームごとの大きなメモリ確保を避ける。
- テキスト・図形の編集はデコード済みフレームへのオーバーレイ描画で完結させ、動画の再デコードや音声停止を行わない。
- ハードウェア／コーデック検出は起動時のUIブロックを避けてバックグラウンドで実行し、QSV未対応環境では初期化プローブ自体を省略する。
- プレビューと音声処理はLinuxの`nice`で低優先度実行する。
- 動作プロファイルに応じてプレビュー解像度、FPS、FFmpegスレッド数を制限する。
- 書き出しはプロジェクトのスナップショットを別スレッドで処理する。
- 元メディアは変更せず、書き出し途中のファイルは成功時のみ完成ファイルへ置換する。
- 音声波形はオンデマンドで一度だけデコードし、`AssetId` ごとにキャッシュする（毎フレーム再計算しない）。

プレビューはクリップごとにFFmpegプロセスを維持する継続デコーダー方式を採用する。QSVを実機初期化できる環境ではQSVデコードと`vpp_qsv`を優先し、未対応コーデックや利用不可環境ではソフトウェア経路へ自動フォールバックする。最終RGBテクスチャ転送のzero-copy化は後続最適化項目とする。
